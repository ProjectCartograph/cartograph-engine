# Add a project or programme as a component

This guide shows you how to record that a project or programme depends on another piece of work. The example is the cooperative's *Quality Check Rollout*, which depends on the *Market Access Programme*.

Both pieces of work must already exist. If the one you depend on does not, [split a large project into components](split-a-large-project-into-components.md) first.

## Steps

1. In the rail, choose **Projects** and select *Quality Check Rollout*.
2. Open the **Context** step. In the **Alignment** section, find the line **Depends on**.
3. Press **Add** (its tooltip reads *Add a project or programme this depends on*). The *Depends on* picker opens.
4. Find the work you depend on. Type in the filter box to narrow the list by name. The buttons beside it show **All**, projects only, or programmes only. Select a row to read it in the panel on the right.
5. Tick the row for *Market Access Programme*. A field appears under its name, *What this needs from it*. Say in a few words what you need from it.
6. Press **Close**. *Market Access Programme* now appears under **Depends on**.

The change is saved in your change set. You edit only this side: the work you depend on does not change.

## If a row is greyed out

A row that says *It already depends on this one, so this would make a loop.* cannot be chosen. Choose different work, or remove the link that runs the other way first. To find and break a loop that already exists, see [Find the critical path and fix a loop](find-the-critical-path-and-fix-a-loop.md).

## Remove a dependency

Beside the name under **Depends on**, press the cross (its tooltip reads *Stop depending on* and the name).
